# PatchCredit 完整实验研究框架（LLM 编译器正式实验版）

> 版本：2026-08-19  
> 目标：在 PatchCredit 通过预实验 Gate 后，形成可直接指导代码实现、实验执行和论文撰写的完整正式实验框架。  
> 核心对象：**LLM Compiler Agent 生成的多动作编译优化计划**。  
> 核心指标：**真实运行时间（runtime）**。  
> 原则：每个阶段必须有明确输入、代码任务、测试、Gate 和产出清单。

---

# 0. 统一定义

给定程序 \(x\)，LLM Compiler Agent 输出：

\[
S_{LLM}=[a_1,\ldots,a_n]
\]

每个 action instance：

```python
@dataclass(frozen=True)
class ActionInstance:
    action_id: str
    pass_name: str
    position: int
    params: dict
    nesting: str | None
    source: str  # llm / agent
```

PatchCredit 输出：

```python
@dataclass
class CreditRecord:
    action_id: str
    credit_mean: float
    credit_ci_low: float
    credit_ci_high: float
    uncertainty: float

@dataclass
class InteractionRecord:
    action_i: str
    action_j: str
    interaction_mean: float
    ci_low: float
    ci_high: float
```

最终：

\[
S_{PC}=Recompose(S_{LLM}, Credit, Interaction)
\]

# E2：LLM Compiler Agent 计划生成

## 目标

生成真正的 PatchCredit 主输入，而不是专家/手工 sequence。

## 约束

LLM 输出必须是结构化 plan：

```json
{
  "task_id": "polybench_2mm",
  "actions": [
    {"pass": "instcombine"},
    {"pass": "loop-unroll", "params": {"count": 4}},
    {"pass": "gvn"}
  ]
}
```

## 代码指导

实现：

```python
class PlanGenerator:
    def generate(self, task, attempt_id: int) -> OptimizationPlan: ...

def validate_plan_schema(plan) -> None: ...
def compile_plan(plan, task) -> BuildResult: ...
def evaluate_plan(plan, task) -> PlanEvalResult: ...
```

必须缓存：

- system/user prompt；
- model；
- sampling params；
- raw response；
- parsed sequence；
- token usage；
- generation seed/attempt id；
- compile/correctness/runtime。

## 数据筛选

进入 PatchCredit 主数据的 plan 必须：

1. compile PASS；
2. correctness PASS；
3. runtime improvement 超过噪声门槛；
4. action count 达到正式最低要求；
5. plan 可重放。

## Gate E2

至少得到足量成功多动作计划。

建议正式实验：
- 每个 task 生成多次；
- 不要求所有 attempt 成功；
- 保存失败 plan 做 failure analysis。

## 产出清单


# E3：Action Instance 表示与合法干预生成

## 目标

把 sequence 变成可干预的 action-instance 结构。

## 代码指导

实现：

```python
@dataclass
class OptimizationPlan:
    plan_id: str
    task_id: str
    actions: list[ActionInstance]

def remove_actions(plan, action_ids: set[str]) -> OptimizationPlan: ...
def remove_block(plan, start: int, end: int) -> OptimizationPlan: ...
def reorder_local(plan, action_ids: list[str], order: list[str]) -> OptimizationPlan: ...
def validate_pipeline(plan) -> ValidationResult: ...
```

第一版：

- 只做 order-preserving deletion；
- 不改变剩余 action 的相对顺序；
- nested pipeline 先只支持可序列化子集。

## Gate E3

- 任意 action 可稳定定位；
- 删除后 pipeline 可序列化；
- validation 能区分语法非法、构建失败和正确性失败；
- 同一 intervention 重放一致。

# E4：小计划 Exact Oracle

## 目标

在 4–8 action 的小计划上穷举 order-preserving deletion subsets，建立 attribution 和 recomposition Ground Truth。

## 代码指导

```python
def enumerate_subplans(plan: OptimizationPlan):
    ...

def evaluate_subplan(plan, task, repeats) -> UtilityRecord:
    ...

def build_exact_oracle(plan_id: str) -> OracleTable:
    ...
```

Utility：

\[
U(S)=-\log(Runtime(S)/Runtime(Base))
\]

correctness failure：

- 不赋正常 runtime utility；
- 单独标记 infeasible；
- 不能当成“很慢”。

## Gate E4

每个 Oracle plan：

- ≥90% 可重放 intervention 有明确状态；
- runtime uncertainty 已记录；
- 能确定 best feasible subplan；
- 能计算 LOO / pair interaction / Oracle rank。

# E5：Contextual Credit 与 Interaction 模型

## 目标

实现正式主创新。

## Baseline 先实现

```python
def prefix_credit(...)
def loo_credit(...)
def pairwise_interaction(...)
def monte_carlo_shapley(...)
```

## PatchCredit

```python
class ContextualCreditEstimator:
    def fit(self, observations, plan, constraints): ...
    def action_credit(self) -> list[CreditRecord]: ...
    def pair_interaction(self) -> list[InteractionRecord]: ...
    def predict_utility(self, candidate_plan) -> Prediction: ...
```

推荐第一版不要追求复杂深度模型，先从：

- weighted local regression；
- sparse main+pairwise model；
- Bayesian linear/heteroscedastic regression；
- bootstrapped ensemble；

中选择可解释、可稳定评估的一种。

## Gate E5

在 E4 Oracle 上，相比简单 LOO 至少在以下一项有明确优势：

- credit rank correlation；
- top-k important action recall；
- strong interaction detection；
- best-subplan prediction；
- uncertainty calibration。

若全部没有优势，主方法降级或 NO-GO。

## 产出清单

```text
outputs/e5/credit_metrics.csv
outputs/e5/interaction_metrics.csv
outputs/e5/calibration.csv
```

# E6：预算化反事实采样

## 目标

在固定真实执行预算下恢复足够有用的 credit 结构。

## 代码指导

统一 sampler：

```python
class Sampler(Protocol):
    def propose(self, history, budget_left: int) -> list[Intervention]: ...
```

实现：

- random；
- size-stratified random；
- LOO-first；
- Shapley permutation；
- uncertainty；
- PatchCredit budgeted；
- hierarchical PatchCredit。

推荐正式 PatchCredit acquisition：

\[
Score(q)
=
\alpha Uncertainty(q)
+\beta DecisionImpact(q)
+\gamma InteractionPotential(q)
-\delta ExpectedCost(q)
-\eta InvalidRisk(q)
\]

## Gate E6

在相同 budget：

- 找到 Oracle top-1 / top-k 的成功率更高；或
- 达到同等 regret 所需 executions 更少；或
- interaction F1 / rank 更高。

# E7：Credit-guided Recomposition

## 目标

从解释转为真实优化。

## V1 搜索空间

- 删除负 credit action；
- 删除低 credit + 高冲突 action；
- 保留 synergy group；
- block prune；
- order-preserving subset search。

## V2

- 对独立 action 做局部 reorder；
- 重复 Pass instance 合并/保留；
- nested pipeline local rewrite。

## 代码指导

```python
def generate_candidates(plan, credits, interactions, k) -> list[OptimizationPlan]:
    ...

def recompose(plan, model, execution_budget) -> RecomposeResult:
    ...
```

## 核心指标

\[
Speedup_{extra}
=
\frac{Runtime(S_{LLM})}{Runtime(S_{PC})}-1
\]

并同时报告：

- vs baseline；
- vs `-O3`；
- plan length；
- executions；
- compile time。

## Gate E7

正式成功线优先看：

- 几何平均 runtime 是否优于原 LLM plan；
- 改善任务比例；

# E10：消融、失败分析与复现包

## 必须消融

- 去掉 interaction；
- 去掉 contextual weighting；
- 只用 LOO；
- random sampling；
- 去掉 uncertainty；
- 去掉 hierarchical screening；
- 不允许 reorder；
- runtime utility 换成 IR instruction count，观察结论差异。

## Failure taxonomy

至少记录：

- compile invalid；
- correctness failure；
- runtime unstable；
- LLM plan no speedup；
- no interaction；
- full plan already optimal；
- sampler miss；
- model misranking；
- recomposition regression。

## 复现包

```text
repro/
├─ env/
├─ configs/
├─ prompts/
├─ accepted_plans/
├─ interventions/
├─ measurements/
├─ scripts/
└─ README.md
```

## 最终 Gate

只有满足：

1. runtime 主结果成立；
2. 结果不是单个 benchmark 驱动；
3. 归因有独立价值；
4. budgeted sampler 有真实必要性；
5. recomposition 的收益超过简单 LOO；

才保留完整三创新点结构。
