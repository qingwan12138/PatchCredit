# PatchCredit 预实验可行性研究框架（LLM 编译器 Go / No-Go 版）

> 版本：2026-08-19  
> 目的：**用最低代码和运行成本判断 PatchCredit 是否存在真实研究现象。**  
> 重要修订：预实验主数据必须来自 **LLM Compiler Agent 实际生成的优化计划**；专家/固定 O3 只用于测量工具校准，不能证明 PatchCredit 对 LLM 有效。  
> 结论必须为：**GO / CONDITIONAL GO / NO-GO**。

---

# 1. 预实验只验证五件事

## F1：LLM 成功优化计划中是否存在负贡献/冗余动作？

如果没有，PatchCredit 的二次优化空间很小。

## F2：是否存在上下文相关的 interaction？

如果每个 action 几乎独立，Contextual Credit 主创新不足。

## F3：完整 LLM plan 是否经常不是最佳子计划？

如果完整 plan 已经最优，recomposition 很难提升性能。

## F4：LOO 是否已经足够？

如果 LOO 用极少测量就能找到近 Oracle 最优方案，则复杂 budgeted estimator 没必要。

## F5：Runtime 信号是否足够稳定？

如果 runtime 噪声大于 action effect，整个课题不应继续。

---

```text

      ↓ Gate 7：能否实际超过 LLM plan？
P8  GO / CONDITIONAL GO / NO-GO
```

## 需要观察四类现象

### 现象 A：负贡献

删除某 action 后更快：

\[
Runtime(S\setminus a_i)<Runtime(S)
\]

### 现象 B：冗余

删除后 performance 几乎不变。

### 现象 C：协同

\[
I_{ij}>NoiseMargin
\]

### 现象 D：完整 Plan 非最优

存在：

\[
S^*\subset S
\]

满足：

\[
Runtime(S^*)<Runtime(S)
\]

## Gate 4：核心 GO/NO-GO Gate

建议 GO 倾向：

- ≥30% plan 有稳定 interaction；
- ≥20% plan 存在更优合法子计划或明显 Pareto 改善；
- negative/redundant actions 不是极少数孤例；
- 这些 effect 大于 runtime noise。

如果这些现象几乎不存在：

> **NO-GO：PatchCredit 核心科学现象不足。**

# P5：PatchCredit-Lite vs 简单基线

## 目标

回答：

> “既然有现象，LOO 不就够了吗？”

## 只实现四个方法

1. Prefix；
2. LOO；
3. Pairwise LOO；
4. PatchCredit-Lite。

PatchCredit-Lite 推荐先用一个很简单的局部 main+pairwise 模型：

\[
\hat U(S)
=
\beta_0
+\sum_i \beta_i x_i
+\sum_{i<j}\beta_{ij}x_ix_j
\]

- ridge/lasso regularization；
- bootstrap uncertainty；
- 仅在原 LLM plan 附近解释。

# P8：最终 Go / No-Go 决策

## 自动决策输入

```text
P0 noise
P3 usable LLM plan count
P4 interaction prevalence
P4 better-subplan prevalence
P5 LOO gap
P6 budget advantage
P7 final extra speedup
```

## GO

满足：

1. 有足够真实 LLM plans；
2. interaction / negative actions 是重复现象；
3. 完整 LLM plan 并非总最优；
4. PatchCredit-Lite 相比 LOO 有价值；
5. budgeted sampling 有潜力；
6. recomposition 能真实提升 runtime。

## CONDITIONAL GO

例如：

- interaction 明显，但 sampler 没优势；
- 可以把论文收缩成“contextual attribution + recomposition”，删除 sampling 创新。

或：

- sampler 有优势，但 final speedup 较小；
- 转为“低预算 plan diagnosis / compactness”论文。

## NO-GO

任一严重情况：

- LLM 成功 plan 几乎无法获得；
- runtime 噪声不可控；
- interaction 稀少；
- full plan 基本总最优；
- LOO 已经完全够用；
- recomposition 反复回退。


# 5. 预实验最小成功故事

理想情况下，最终你能拿到类似：

```text
Task X
Baseline:     100 ms
LLM plan:      82 ms

LLM plan:
[A, B, C, D, E, F]

Oracle:
- C = negative in current context
- B+E = synergy
- D = redundant
- best subset = [A, B, E, F]

PatchCredit-Lite:
用 12 次测量找到 [A, B, E, F]

Final:
PatchCredit = 75 ms
```

这一个案例不能证明论文成立，但如果在多个真实 LLM plans 上重复出现，就说明方向值得进入正式实验。

# 6. 最关键的原则

> **预实验不是证明 PatchCredit 一定有效，而是尽快发现它为什么可能无效。**

特别是 P4、P5、P7：

- P4：有没有现象；
- P5：简单 LOO 能不能替代；
- P7：最终有没有真实性能收益。

这三个 Gate 不过，不进入正式 E0–E10。
