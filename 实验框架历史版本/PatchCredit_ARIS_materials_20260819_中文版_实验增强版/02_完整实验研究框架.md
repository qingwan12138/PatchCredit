# PatchCredit 完整实验研究框架（正式实验版）

> 版本：2026-08-19  
> 定位：用于 PatchCredit 通过预实验 Gate 后的正式论文实验与工程实现。  
> 核心目标：验证“编辑级性能贡献 + 非加性交互建模”是否能在有限真实执行预算下，指导 LLM 多编辑性能优化 Patch 的重组，并得到正确、稳定、达到或超过原始 Patch 性能的结果。

---

## 0. 研究问题与正式假设

### RQ1：性能贡献是否可恢复？
对一个由多个编辑单元组成的优化 Patch，能否稳定估计每个编辑单元的性能贡献，并在可穷举的小 Patch 上接近 Oracle？

### RQ2：编辑交互是否真实且重要？
LLM/专家优化 Patch 中，是否普遍存在“单个编辑效果弱，但组合后显著加速”的协同，或“两个单独有效的编辑组合后互相抵消”的冲突？

### RQ3：有限预算下能否恢复足够的贡献/交互结构？
相对随机采样、LOO、ddmin、简单回归模型，PatchCredit 能否用更少的编译与运行测量找到近最优组合？

### RQ4：归因能否产生实际性能收益？
利用贡献和交互信息重组后的 Patch，能否在保证正确性的前提下达到或超过完整 LLM Patch 的运行时性能？

### RQ5：LLM 组件是否必要？
LLM 提出的“语义编辑单元/交互假设”是否能够提高合法子集比例、降低测量预算或提高最优组合发现率；若不能，则必须如实降级为非核心组件。

## 2. 全局代码原则

1. **Benchmark 适配层与算法层严格解耦**：任何 GSO/SWE-fficiency 特殊命令只能出现在 `benchmark/` 适配器中。
2. **每次测量可复现**：保存 commit、Patch hash、编译器版本、CPU 信息、环境变量、输入规模、重复次数、原始运行时间序列。
3. **禁止只存均值**：必须保存每一次 raw timing。
4. **正确性先于性能**：子集未通过 build/test，则状态为 `INFEASIBLE`，不得把其 runtime 当作普通低性能样本。
5. **任何算法决策均可回放**：sampler 每一步必须保存当前观测、候选集、打分、选择原因和随机种子。
6. **不允许手工修改实验结果文件**：所有 summary CSV/JSON/图表由脚本从 raw artifact 自动生成。

## Stage E1：Benchmark 接入与任务筛选

### 目标
构造正式任务池，不直接把所有 benchmark 任务无差别塞入 PatchCredit。

### 数据层级

**主任务池**：GSO + SWE-fficiency 中可稳定复现的多编辑优化任务。  
**外部验证池**：SWE-Pro 中可接入的任务。  
**可控池**：PolyBench/C 或自建小 kernel，用于已知交互结构验证。

GSO 原始工作包含 102 个任务/10 个代码库；SWE-fficiency 包含 498 个任务/9 个仓库；SWE-Pro 来源于 102 个专家优化。正式实验必须重新筛选稳定任务，不能默认 benchmark 所有任务均适用于细粒度 attribution。

### 代码指导
统一接口：

```python
class BenchmarkAdapter(ABC):
    def list_tasks(self) -> list[str]: ...
    def checkout(self, task_id: str, dst: Path) -> TaskWorkspace: ...
    def apply_reference_patch(self, ws) -> None: ...
    def run_correctness(self, ws) -> TestResult: ...
    def run_performance(self, ws, repeat: int) -> TimingResult: ...
```

筛选脚本必须自动计算：

- baseline 是否通过 correctness；
- reference patch 是否通过 correctness；
- reference patch 是否有稳定 speedup；
- patch 修改文件数、hunk 数、初步编辑数；
- runtime noise floor。

### 验收 Gate

任务进入 `accepted_tasks.jsonl` 必须同时满足：

1. baseline / full patch 均正确；
2. full patch 的 95% CI 与 baseline 能区分，或达到预先定义的 practical-effect threshold；
3. patch 可拆成至少 3 个、最好 4–12 个编辑单元；
4. 性能测试可以重复自动执行；
5. 不包含明显 benchmark hacking。

### 产出清单

- `artifacts/stage01_dataset/all_tasks.jsonl`
- `artifacts/stage01_dataset/screening.csv`
- `artifacts/stage01_dataset/accepted_tasks.jsonl`
- `artifacts/stage01_dataset/rejected_tasks.csv`
- `artifacts/stage01_dataset/task_selection_report.md`

## Stage E2：Patch 编辑单元划分与依赖图

### 目标
把一个完整 Patch 转换成可组合、可执行、依赖闭合的语义编辑单元。

### 代码指导

第一层使用 deterministic parser：

```python
parse_git_diff(diff_text) -> list[Hunk]
map_hunk_to_ast(hunk, source_tree) -> ASTContext
build_static_units(hunks, ast_contexts) -> list[EditUnit]
build_dependency_graph(units, source_tree) -> nx.DiGraph
closure(unit_set, dep_graph) -> frozenset[str]
```

推荐实现：

- Git diff 解析：`unidiff` 或自写 parser；
- 多语言 AST：tree-sitter；
- C/C++ 可附加 clang AST/符号信息；
- 依赖边至少覆盖：同一符号定义-使用、import/include、新增 helper 与调用点、接口签名与调用方、同一数据结构字段变更。

第二层才是 LLM unitizer：只允许输出结构化 JSON：

```python
llm_propose_units(diff, static_context) -> UnitProposal
validate_llm_units(proposal, diff) -> ValidationResult
```

任何 LLM 单元必须满足：所有 diff 行恰好被覆盖，不可凭空产生代码；重叠/遗漏直接拒绝。

### 单元测试要求

- diff 行覆盖率 = 100%；
- 每个 unit 可以独立重放或通过依赖闭包重放；
- closure 操作幂等；
- 相同输入和固定配置得到相同 static units。

### 验收 Gate

- ≥90% 入选 Patch 可得到 3 个以上依赖闭合单元；
- 依赖闭包后可构造多个不同合法候选；
- 随机抽查至少 20 个 Patch，人工审计 unit 边界和依赖边。

### 产出清单

- `artifacts/stage02_units/<task>/patch_units.json`
- `artifacts/stage02_units/<task>/dependency_graph.graphml`
- `artifacts/stage02_units/<task>/unit_coverage.json`
- `artifacts/stage02_units/manual_audit.csv`
- `artifacts/stage02_units/unitization_report.md`

## Stage E3：正确性门控与运行时噪声校准

### 目标
建立可信的“子集 → correctness → runtime”测量器。

### 代码指导

```python
materialize_subset(task, unit_ids) -> Workspace
build_subset(ws) -> BuildResult
run_correctness_gate(ws) -> TestResult
measure_runtime(ws, policy) -> TimingResult
estimate_noise(raw_times) -> NoiseProfile
```

`measure_runtime` 要支持：

- warmup 次数；
- 正式 repeat 次数；
- CPU affinity；
- 每个 candidate 运行顺序随机化；
- interleaved A/B 测量；
- timeout；
- outlier 只允许按预注册规则处理，不可看结果后手工删除。

默认推荐以 median runtime 为主统计量，同时保存全部 raw times；最终显著性使用 bootstrap CI 或适合配对运行设计的区间估计。

### 验收 Gate

- 基线重复 session 的 runtime 波动低于预设 noise threshold；
- 若某 task 的最小可检测差异大于 patch 间差异，则标记 `NOISY` 并剔除 attribution 主分析；
- measurement harness 的同一 commit 重测结果一致。

### 产出清单

- `artifacts/stage03_measurement/noise_profiles.jsonl`
- `artifacts/stage03_measurement/repeatability.csv`

## Stage E4：小 Patch 穷举 Oracle 数据集

### 目标
为后续贡献估计和预算采样提供真实可验证的 Ground Truth。

### 适用范围
仅对依赖闭合后 `n <= 8`（预实验建议更小）的 Patch 穷举；若合法子集远少于 `2^n`，则记录全部合法闭包集合。

### 代码指导

```python
enumerate_dependency_closed_subsets(units, graph) -> Iterable[Subset]
evaluate_subset(task, subset) -> MeasurementRecord
build_oracle_table(records) -> OracleTable
```

定义性能效用：

\[
v(S)=\log\frac{T_{base}}{T(S)}
\]

其中不正确/不能构建的 S 标记为 infeasible，不混入普通 performance utility。

Oracle 至少计算：

- 最佳正确子集；
- 完整 Patch 排名；
- exact/conditional Shapley-style credit（仅在合法 coalition 空间内）；
- LOO credit；
- pairwise interaction；
- Pareto frontier：speedup vs 编辑数。

### 验收 Gate

- 至少形成足够数量的小 Patch oracle task；
- 每个 oracle task 的所有合法子集均有完整 correctness 与 raw timing；
- 能够明确回答“full patch 是否最优”“是否存在负贡献”“是否存在 interaction”。

### 产出清单

- `artifacts/stage04_oracle/<task>/subsets.jsonl`
- `artifacts/stage04_oracle/<task>/measurements.jsonl`
- `artifacts/stage04_oracle/<task>/oracle_credit.json`
- `artifacts/stage04_oracle/<task>/interaction_matrix.csv`
- `artifacts/stage04_oracle/oracle_summary.csv`

## Stage E5：Performance Credit 与 Interaction 模型

### 目标
实现论文主创新，并在 Oracle 集上验证“估计是否可信”。

### 至少实现的模型

Baseline：

- LOO；
- exact/approximate Shapley；
- 稀疏线性模型；
- LASSO with pairwise terms；
- GBDT/XGBoost 类非线性模型（只作为强 baseline，不把模型复杂度当创新）。

PatchCredit 主模型建议接口：

```python
class CreditModel:
    def fit(self, observations, units, graph) -> None: ...
    def credit(self) -> dict[str, Estimate]: ...
    def interactions(self) -> dict[tuple[str,str], Estimate]: ...
    def predict(self, subset) -> Estimate: ...
    def uncertainty(self, subset) -> float: ...
```

interaction 的最基本可解释量：

\[
I_{ij}(S)=v(S\cup\{i,j\})-v(S\cup\{i\})-v(S\cup\{j\})+v(S)
\]

实际模型可对多个 context S 聚合并提供置信区间。

### 评测

- credit 排名与 oracle 的 Spearman/Kendall；
- interaction sign/Top-K 恢复率；
- subset utility prediction error；
- uncertainty calibration；
- repeated-session stability。

### 验收 Gate

PatchCredit 必须至少在一项“真正影响重组”的指标上优于 LOO/简单模型，而不是只把相关系数提高一点点。

### 产出清单

- `artifacts/stage05_credit/model_results.csv`
- `artifacts/stage05_credit/credit_rankings.jsonl`
- `artifacts/stage05_credit/interaction_recovery.csv`
- `artifacts/stage05_credit/calibration.csv`
- `artifacts/stage05_credit/ablation_static_vs_llm.csv`

## Stage E6：Budgeted Interaction Sampling

### 目标
在不能穷举的真实 Patch 上，只测最有价值的子集。

### 核心算法接口

```python
class Sampler:
    def initialize(self, task, units, graph, budget): ...
    def suggest(self, observations, k=1) -> list[Subset]: ...
    def update(self, new_observations): ...
```

PatchCredit acquisition score 至少考虑：

- 预测不确定性；
- 潜在 interaction residual；
- 对当前最优候选排序的影响；
- dependency closure 成本；
- correctness 失败风险；
- 实际测量成本。

必须实现 baselines：

- random subset；
- stratified random；
- LOO-first；
- ddmin/TRIM-style hierarchical deletion；
- uncertainty-only；
- model-only greedy。

### 两级评估

**离线 Oracle replay**：从 Stage E4 的真值表里模拟 10%、25%、50%、75% 测量预算。  
**在线真实测量**：在 8–15 unit Patch 上实际调用 runner。

### 主指标

- best-found utility / oracle-best utility；
- regret；
- 找到 top-5% 候选的概率；
- 达到 95% oracle utility 所需 measurements；
- wall-clock cost。

### 产出清单

- `artifacts/stage06_sampling/offline_budget_curves.csv`

- `artifacts/stage06_sampling/regret.csv`

## Stage E7：Performance-guided Patch Recomposition

### 目标
把“解释”转化为“性能优化结果”。

### 代码指导

```python
generate_candidates(credit, interactions, graph, k) -> list[Subset]
search_recomposition(model, sampler_state, constraints) -> list[Subset]
verify_candidates(task, candidates) -> list[VerifiedCandidate]
select_final_patch(candidates, objective) -> VerifiedCandidate
```

默认目标：

\[
\max_{S \subseteq P} v(S)-\lambda C(S)
\]

约束：

- correctness = pass；
- dependency closed；
- 不允许 benchmark hack；
- 最终性能必须真实执行验证。

其中 `C(S)` 可取编辑单元数或 changed LOC，仅作为次级复杂度项。

### 必须比较

- Full Patch；
- LOO prune；
- ddmin；
- TRIM-style deletion；
- random search；
- GBDT/model search；
- PatchCredit recomposition。

### 主结果

1. 相对 baseline 程序 speedup；
2. 相对 full LLM patch 的额外 speedup；
3. 若无法更快，是否在性能无显著下降时明显减少编辑；
4. worst-case regression。

### 产出清单

- `artifacts/stage07_recompose/candidates.jsonl`
- `artifacts/stage07_recompose/final_patches/<task>.diff`
- `artifacts/stage07_recompose/recomposition_results.csv`
- `artifacts/stage07_recompose/pareto_frontiers.csv`

## Stage E9：正式全量评测

### 目标
形成论文主表。

### 实验分组

**E9-A Oracle 小 Patch**：验证 credit/interaction 恢复。  
**E9-B Expert Patch**：验证真实优化 Patch 是否存在可重组空间。  
**E9-C LLM Patch**：论文主场景。  
**E9-D Cross-benchmark**：至少一个未参与开发调参的外部 benchmark。  
**E9-E Controlled kernels**：验证已知 interaction 的恢复正确性。

### 统计要求

- 报告 task-level 分布，不只报告 aggregate mean；
- speedup 同时给 median、IQR/CI；
- 主结论给 paired comparison；
- multiple seeds/session；
- 预先固定 outlier 规则；

# 第三部分：统一命令约定

建议所有阶段最终可用 CLI 串起来：

```bash
# 环境
python -m patchcredit.cli env check --config configs/common.yaml

# 数据接入与筛选
python -m patchcredit.cli dataset ingest --config configs/formal/gso.yaml
python -m patchcredit.cli dataset screen --benchmark gso

# Patch 拆分
python -m patchcredit.cli patch decompose --task TASK_ID --mode static
python -m patchcredit.cli patch decompose --task TASK_ID --mode llm-assisted

# 噪声校准
python -m patchcredit.cli measure calibrate --task TASK_ID

# Oracle
python -m patchcredit.cli oracle enumerate --task TASK_ID
python -m patchcredit.cli oracle run --task TASK_ID

# Credit/interaction
python -m patchcredit.cli credit fit --task TASK_ID --model patchcredit

# Budgeted sampling
python -m patchcredit.cli sample run --task TASK_ID --budget 0.5

# 重组
python -m patchcredit.cli recompose run --task TASK_ID

# 最终评测
python -m patchcredit.cli evaluate formal --config configs/formal/gso.yaml
```

每条 CLI 必须：

- 非 0 退出码表示失败；
- 输出 structured log；
- 支持 `--seed`；
- 支持 `--resume`；
- 不覆盖历史 raw artifact，使用 run_id 新建目录。

# 第四部分：论文最终成功标准

PatchCredit 不要求所有 task 都进一步加速；正式成功应同时体现三类价值。

## 一级目标：性能

- 在有重组空间的 LLM Patch 上，相对完整 Patch 获得稳定的额外 runtime 改善；
- 或在相同/近似性能下，以更少编辑达到 Pareto 改善；
- worst-case regression 可控。

## 二级目标：归因

- 小 Patch 上 credit 与 interaction 能被 Oracle 验证；
- 结果跨重复 session 稳定。

## 三级目标：成本

- 相比穷举，以显著更少的实际测量找到近最优组合；
- 同预算下优于 random/LOO/ddmin 等简单方法。

**论文最强叙事不是“Patch 变短”，而是：PatchCredit 通过真实运行反事实测量恢复 LLM 多编辑优化中的性能贡献和交互结构，并利用这些结构在有限测量预算下找到更优的正确 Patch。**
